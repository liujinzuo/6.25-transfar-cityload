# cityload —— 城市配送智能配载与调度

> **传化 × 动势 · AI重构产业·架构师大赛** ｜ **AI＋物流赛道**
> 重点推荐场景：**城市配送智能配载（多约束条件下的车辆配载与运输调度优化）**

面向连锁药店城配场景：中心仓每天向多家门店配送数百个 SKU，
在**车厢容量、载重、货物耐压、品类合规、交付时间窗**等多重约束下，
自动完成 **车厢空间分配** 与 **不同品类货物的合理摆放**，并联动生成配送路径。

---

## 0. 一句话说清做了什么

把「一车货怎么摆」拆成两个可解释、可核查的问题：

**① 空间怎么分？** —— 按品类合规要求把车厢沿车长切成连续**功能区**，
再用闭环回检（试装 → 按未装载情况重新分配 → 再试装）确定每个功能区的长度。

**② 不同种类的货怎么摆？** —— 由一张显式的**品类装载规则表**驱动落位：
禁压上限、品类不相容、重货置底、易碎件置顶、底面支撑率、
并在每个功能区内按**交付顺序的逆序**逐店码放，做到「卸货不倒腾」。

## 2. 空间分配：车厢怎么切

### 2.1 一级 —— 品类功能区（合规硬隔离）

规则表见 [`cityload/categories.py`](cityload/categories.py)。
车身从车头到**尾门**依次为：

| 位置 | 功能区 | 承接品类 | 分配依据 |
|------|--------|----------|----------|
| 车头侧 | **精密器械区** | 家用医疗器械 | 禁压、需稳固，放最里侧 |
| 中段 | **常规药品区** | 口服药品 / 外用药品 / 保健品 | 主力货量，居中 |
| 中段偏门 | **日化隔离区** | 医用日化耗材 | 独立成段，避免与药品交叉污染 |
| 贴尾门 | **冷链温控区** | 冷链生物制品 | 温控优先，需最快取出 |

功能区是**硬边界**：货物不得越区（越区会被 `zone_violations` 指标抓到）。

### 2.2 二级 —— 功能区内逐店码放（交付顺序逆序）

功能区内**不再切细条**。切细条的直觉看似合理，实测会把一个门店在一个功能区里的货
逼成一根高塔：细条宽度只有一两百毫米，塞不下整箱垛，货物只能向全车逃逸，
功能区彻底失效（实测装载率从 27.8% 掉到 23.6%，并产生 45 个未装载箱垛）。

改为**功能区内逐店顺序码放**：从**最后交付**的门店开始装，每个门店自己的整箱垛
按尺寸从大到小落位，在功能区内自然聚成连续一段；后面的门店依次向尾门方向接续。
效果是卸第 k 站时只需到各功能区取出属于该站的那一段，**不必挪动别站货物**。

### 2.3 空间分配是闭环，不是一次性估算

```python
zone_segs = allocate_space(...)            # 初分配：按体积占比 + 最小可容纳长度保底
for _ in range(zone_realloc_rounds):       # 回检：装不下就重新分配
    placed, left = _pack_store_major(...)
    if not left: break
    weights = {z: base_vol[z] + 2.0 * unplaced_vol[z] for z in zones}
    zone_segs = _allocate(weights, mins, usable_l)
```

装不下的功能区自动加长、其余相应缩短，直到全部装下或达到轮数上限。
**空间分配本身是被求解的，而不是拍脑袋的**。

## 3. 品类码放规则（`categories.py`）

| 品类 | 功能区 | 单箱可承压 | 重货置底 | 优先卸货 | 不相容品类 |
|------|--------|-----------|---------|---------|-----------|
| 冷链药品 | COLD | **0 kg（禁压）** | — | ✔ | — |
| 医疗器械 | PRECISE | **0 kg（禁压）** | — | — | 日化耗材 |
| 口服药品 | AMBIENT | 45 kg | — | — | 日化耗材 |
| 外用药品 | AMBIENT | 30 kg | — | — | 日化耗材 |
| 保健品 | AMBIENT | 50 kg | — | — | 日化耗材 |
| 日化耗材 | ISOLATED | 60 kg | ✔（底面 ≤ 500mm） | — | 药品与器械全类 |

配载器逐条强制这些规则：

- **禁压上限**：单箱上方压载 = Σ(压在上面的箱垛重量 × 支撑面重叠比例)，
  超过 `max_load_above_kg` 的候选位直接否决。冷链与精密器械为 0，上方永远不放货。
- **品类不相容**：`incompatible` 中的品类不得**直接上下相邻**，防泄漏与交叉污染。
- **重货置底**：日化耗材的**底面**必须落在车厢下层 500mm 以内
  （注意是底面而非顶面 —— 用顶面判断会把所有高箱垛直接判死，这是个真实的坑）。
- **易碎件置顶**：易碎件上方不得再压任何货。
- **底面支撑率** ≥ 75%（由车厢地板或下方箱顶提供）。

## 4. 排线与车型（配角，但仍是方案的一部分）

- **节约算法（Clarke-Wright）+ 2-opt**：同时考虑载重、容积与到货时间窗。
- **发车时刻是决策变量**：一条只服务 14:00–17:00 时间窗门店的线路应当 13:00 发车，
  而不是 06:00 到场干等 8 小时。解析解：
  `t = max(仓开时间, max_i(tw_start_i − c_i))`，可行上界 `min_i(tw_end_i − c_i)`。
- **可执行性硬约束**：时间窗达成、单车在线时长 ≤ 10h、单车累计等待 ≤ 150min。
- **配载感知的车型指派**：按单位成本从低到高**逐个车型试装**，
  第一个真正装得下的车型即为指派结果 —— 排线与装车不割裂。
  装车装得紧，就能用更小更便宜的车。
- **批量搜索**：路径批量（单条路径能装多大）本身参与总成本择优。

## 5. 对照实验设计（2×2 消融 + 因子独立归因）

| 代号 | 路径方法 | 装载方法 | 作用 |
|------|----------|----------|------|
| **A** | 最近邻贪心（人工经验） | 全区集中码放 | 基线 |
| **B** | 最近邻贪心 | **品类功能区 + 交付逆序** | 只检验空间分配的价值 |
| **C** | **节约算法 + 2-opt** | 全区集中码放 | 只检验路径优化的价值 |
| **D** | **节约算法 + 2-opt** | **品类功能区 + 交付逆序** | 综合方案 |

A/B 与 C/D 各自共用同一组路径，装车器与排序规则完全一致，
**唯一变量是「是否启用空间分配」**，因此收益可以干净地归因，而不是混在一个总数里。

### 实测结果（8 门店算例，空间分配完整生效）

| 指标 | A（基线） | B | C | **D（本方案）** |
|------|---|---|---|----------------|
| 车辆数 / 里程 / 成本 | 3 / 65.7km / 905 元 | 3 / 65.7km / 905 元 | 3 / 62.0km / 898 元 | **3 / 62.0km / 898 元** |
| **重复搬运段数** | 37 | 37 | 31 | **6（−83.8%）** |
| **空间分配降级车次** | 3 | 1 | 3 | **0** |
| **越区箱垛数** | 0 | 0 | 0 | **0** |
| 未装载整箱垛 | 0 | 0 | 0 | **0** |

**空间分配在全部 3 台车上按最高等级执行，品类零越区，重复搬运段数下降 83.8%，
且运输指标（车辆数/里程/成本）零代价。**

### 实测结果（30 门店紧装载算例）与已知限制

| 指标 | A | B | C | D |
|------|---|---|---|---|
| 里程（km） | 268.3 | 268.3 | **236.4** | **236.4** |
| 总成本（元） | **4548.6** | 4548.6 | 5259.7 | 5259.7 |
| 重复搬运段数 | 500 | 500 | 455 | **446** |
| 空间分配降级车次 | 4/4 | 4/4 | 6/6 | **5/6** |

在装载偏紧、单车站点数多时，**一维功能区与高装载率存在结构性冲突**：
功能区的**地板面积**不足以让每家门店各自成段，算法按设计降级（并记录为指标），
于是 B ≈ A、D ≈ C，空间分配的收益未能兑现。
成因、证据与改进路线见 [docs/05](docs/05-评测结果.md) §3 与 [docs/06](docs/06-当前限制与落地路径.md) §1。

## 6. 评价指标（`cityload/metrics.py`）

| 指标 | 含义 |
|------|------|
| 车辆数 / 总里程 / 总成本 | 运输成本侧 |
| **容积利用率 / 载重利用率** | 装载率侧（赛题明确要求“提升车辆装载率与空间利用率”） |
| 时间窗达成率 / 单车最长等待 / 最长线路用时 | 交付时效侧 |
| **重复搬运段数（倒腾指数）** | 装卸效率侧，本方案自定义 |
| 未装载整箱垛 / 越区箱垛 | 可行性与合规性 |
| 求解耗时 | 计算效率 |

**重复搬运段数**是该场景的关键自定义指标，且**按功能区分别计算**：

```
某功能区倒腾次数 = 该功能区卸货序列（按 x 从尾门往里）的门店分段数 − 覆盖到的门店数
```

跨功能区卸货不计倒腾（品类隔离下本来就得分区取货）；
真正造成倒腾的是同一功能区内、同一门店的货被别站切成几段。
空间分配对齐交付顺序时，该指标理论下界为 **0**。

## 7. 代码结构

```
cityload/
├── categories.py     # 品类装载规则表（功能区、禁压、不相容、重货置底）   ← 业务规则
├── domain.py         # 领域模型：SKU/门店/车辆/整箱垛/落位/方案
├── data_synth.py     # 合成算例生成（固定种子，可复现）
├── dataio.py         # CSV 导出/载入（真实数据替换入口）
├── geo.py            # 路网近似：里程与行驶时间
├── routing.py        # 节约算法 + 2-opt + 时间窗/工时约束 + 最优发车时刻
├── packing.py        # ★ 空间分配 + 3D 落位引擎（本方案核心）
├── baseline.py       # 人工经验排线基线
├── metrics.py        # 指标计算与改善幅度对比
├── pipeline.py       # 流水线：排线 → 配载 → 车型指派 → 指标 → 对照实验
├── visualize.py      # 自包含等轴测 3D 装卸示意图
├── report.py         # Markdown / JSON 报告
└── cli.py            # 命令行入口
```
