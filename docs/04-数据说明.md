# 04 · 数据说明

## 1. 数据来源声明

**仓库内全部算例均为程序化合成的模拟数据。**

- 生成器：`cityload/data_synth.py`
- 随机种子：`configs/*.json` 中的 `seed`（默认 `20260214`）
- **同一种子必得同一组数据**，便于评审复现（`tests/test_pipeline.py::test_results_are_reproducible` 强制校验）

数据中**不含**传化集团或任何客户的真实门店、商品、订单、价格与运力信息。

## 2. 字段结构（与赛题“数据示例参考”对应）

| 赛题数据类别 | 本仓库文件 | 字段 |
|-------------|-----------|------|
| **订单与货物数据** | `data/synthetic/order_lines.csv` | `store_id, sku_id, qty` |
| | `data/synthetic/skus.csv` | `sku_id, name, category, length_mm, width_mm, height_mm, weight_kg, fragile, max_stack_units` |
| **车辆与运力数据** | `data/synthetic/vehicles.csv` | `type_id, name, inner_length_mm, inner_width_mm, inner_height_mm, max_payload_kg, fixed_cost, cost_per_km, count` |
| **配送网络数据** | `data/synthetic/stores.csv` | `store_id, name, x_km, y_km, tw_start_min, tw_end_min, service_min` |
| **装载与调度规则** | `configs/default.json`、`cityload/categories.py` | 支撑率、单柱高度、禁压上限、品类不相容、重货置底、工时与等待上限 |

**替换为真实数据**：保持表头一致，然后

```bash
python -m cityload.cli all --data path/to/csv_dir
```

算法代码一行都不用改。载入入口见 `cityload/dataio.py`。

## 4. 人工设定的参数（必须由业务方核实）

下列参数**不是从数据中学出来的**，而是人工假设值。它们是方案结论的敏感输入，
已在配置文件中集中暴露，便于业务方替换为真实口径：

| 参数 | 取值 | 位置 | 说明 |
|------|------|------|------|
| 路网绕行系数 `detour_factor` | 1.25 | `network` | 直线距离 × 1.25 近似城市路网里程 |
| 平均车速 `speed_kmh` | 30 | `network` | 城市配送平均车速 |
| 中心仓开工时刻 `depot_open_min` | 420（07:00） | `network` | — |
| 单车最长在线时长 `max_route_duration_min` | 600（10h） | `network` | 单车单日工时上限 |
| 单车累计等待上限 `max_route_wait_min` | 150 | `network` | 防止为凑单而长时间干等 |
| 车辆固定成本 / 里程成本 | 见 `fleet` | `configs/*.json` | 4.2m 蓝牌 400 元 + 4.0 元/km；3.6m 新能源 260 元 + 1.9 元/km；6.8m 黄牌 780 元 + 7.4 元/km |
| 品类可承压上限 | 见 `categories.py` | `cityload/categories.py` | 冷链/器械为 0（禁压） |
| 品类不相容关系 | 见 `categories.py` | 同上 | 日化与药品/器械互斥 |
| 重货底面高度上限 | 500 mm | `packing.heavy_bottom_max_z_mm` | 日化必须置于下层 |
| 底面支撑率 | 0.75 | `packing.min_support_ratio` | 稳定性与空间利用的折中 |
| 单柱高度上限 | 车厢可用高的 55% | `packing.max_block_height_ratio` | 保证两柱可叠放 |
| 排线容积折减 | 0.55 | `packing.planning_volume_derate` | 装载器**实测可达效率**的标定值 |

> `planning_volume_derate = 0.55` 是排线与配载之间的接口标定值，
> 来自 `docs/05-评测结果.md` 中装载器的实测装载率。若后续更换装载器，
> 该值必须重新标定，否则会出现「路径排得很漂亮但装不下」的割裂。

## 5. 敏感性与稳健性

- **随机种子**：更换种子会改变具体数字，但 A/B/C/D 四方案的相对关系稳定
  （多组种子验证，见 `docs/05-评测结果.md` 的多算例表）。
- **成本模型**：车辆固定/里程成本是结论的敏感输入。方案在 `reports/benchmark.json`
  中输出完整的成本分解（固定成本 / 变动成本），便于按不同口径重算。
- **需求规模**：`configs/test.json` 提供 8 门店的小算例，
  一份配置两用 —— 既是单元测试与快速验证的算例，
  也是**空间分配完整生效**的演示算例（`reports/compact/`），
  因为装载宽松时品类功能区能按最高等级落地。
