# 05 · 评测结果

> 数据来源：`reports/benchmark.json`（30 门店算例）与 `reports/compact/benchmark.json`（8 门店算例）。
> 全部为程序化合成的模拟数据。复现命令见文末。

## 1. 对照实验设计

2×2 消融，A/B 与 C/D 各自共用同一组路径，装车器与排序规则完全一致，
**唯一变量是「是否启用两级空间分配」**，收益可干净归因：

| 代号 | 路径方法 | 装载方法 |
|------|----------|----------|
| **A** | 最近邻贪心（人工经验排线） | 全区集中码放（人工经验装车） |
| **B** | 最近邻贪心 | **品类功能区 + 交付逆序逐店码放** |
| **C** | **节约算法 + 2-opt** | 全区集中码放 |
| **D** | **节约算法 + 2-opt** | **品类功能区 + 交付逆序逐店码放** |

## 2. 算例一：8 门店 / 4.16 m³（装载宽松）

| 指标 | A | B | C | **D（本方案）** |
|------|---|---|---|----------------|
| 车辆数（台） | 3 | 3 | 3 | **3** |
| 总里程（km） | 65.7 | 65.7 | 62.0 | **62.0** |
| 总成本（元） | 905 | 905 | 898 | **898** |
| 容积利用率 | 11.9% | 11.9% | 11.9% | **11.9%** |
| 载重利用率 | 14.6% | 14.6% | 14.6% | **14.6%** |
| 时间窗达成率 | 100% | 100% | 100% | **100%** |
| **重复搬运段数** | 37 | 37 | 31 | **6** |
| **空间分配降级车次** | — | 1 | — | **0** |
| **越区箱垛数** | — | 0 | — | **0** |
| 未装载整箱垛 | 0 | 0 | 0 | **0** |
| 求解耗时（s） | 0.34 | 0.69 | 0.25 | **0.07** |

> 「—」表示该方案本就不做空间分配（`allocation_tier = 0`，不适用，不计为降级）。

### 结论

- **两级空间分配在 3 台车上全部按最高等级执行**（降级 0 车次、越区 0 箱垛），
  即：冷链温控区、日化隔离区、常规药品区、精密器械区**完全按品类隔离**，
  且货物没有一件越出所属功能区。
- **重复搬运段数从 37 降到 6，降幅 83.8%**，即现场卸货时几乎不需要
  「把别人的货挪开再放回」。
- **代价为零**：车辆数、里程、成本与纯成本导向的方案（C）完全一致。
- 求解反而更快（0.07s）—— 分区后每台车的搜索空间被划分得更小。

> 这是本方案设计意图**被完整兑现**的场景：空间分配既拿到了品类合规，
> 又没有牺牲任何运输指标。

## 3. 算例二：30 门店 / 45.5 m³（紧装载，赛题规模）

对齐赛题“中心仓每天向 30 家连锁药店配送数百个 SKU”的规模。

| 指标 | A | B | C | D（本方案） |
|------|---|---|---|-------------|
| 车辆数（台） | 4 | 4 | 6 | 6 |
| 总里程（km） | 268.3 | 268.3 | **236.4** | **236.4** |
| 总成本（元） | **4549** | 4549 | 5260 | 5260 |
| 容积利用率 | 31.8% | 31.8% | 25.3% | 25.3% |
| 载重利用率 | 31.6% | 31.6% | 24.7% | 24.7% |
| 时间窗达成率 | 100% | 100% | 100% | 100% |
| 重复搬运段数 | 492 | 492 | 450 | **441** |
| **空间分配降级车次** | — | 4 | — | **5** |
| **越区箱垛数** | — | 0 | — | 1 |
| 未装载整箱垛 | 54 | 54 | 0 | 0 |
| 求解耗时（s） | 38.4 | 73.3 | 28.0 | 54.7 |

### 结论（这是本方案当前最主要的不足）

- **B 与 A 完全一致、D 与 C 几乎一致** —— 也就是说，
  在 30 门店的紧装载算例上，**空间分配的设计收益没有兑现**。
  原因不是算法没跑，而是它**主动降级了**：
  D 的 6 台车里只有 1 台维持严格品类分区（等级 1），4 台降到等级 3（完全不做分配）；
  B 的 4 台车全部降到等级 3。
- 根本原因已在 [docs/06](06-当前限制与落地路径.md) §1 定位：
  功能区长度按**底面面积**分配，而单个功能区要同时容纳 7 家门店；
  在装载偏紧时，各功能区的**地板面积**不足以让每家门店各自成段，
  于是装不下的箱垛触发降级。
- 路径优化（A→C）在里程上确实有效（**−11.9%**），但要多用 2 台车，
  总成本反而上升 —— 这符合直觉：线路更短更碎，固定成本上去了。
- A 自己也有 58 个箱垛装不下（即人工经验排线给出的大单本身超出了单车能力），
  这反而是「排线与装车割裂」的真实写照；C/D 借助配载感知的车型指派与
  路径批量搜索消除了未装载。

## 4. 把两个算例放在一起看

| | 8 门店（宽松） | 30 门店（紧装载） |
|---|---|---|
| 空间分配是否生效 | ✔ 全部车次最高等级 | ✗ 多数车次降级 |
| 品类隔离是否达成 | ✔ 越区 0 箱垛 | 注意：越区 2 箱垛 |
| 倒腾改善 | **−83.8%** | −10.8% |
| 运输指标代价 | 无 | 无（但也没拿到收益） |

**这给出了本方案真实的适用边界**：当单车装载宽松、单车站点数较少时，
品类功能区能完整落地并显著改善装卸效率；
当单车装载紧张、单车站点数多时，一维功能区与高装载率存在结构性冲突，
需要按 [docs/06](06-当前限制与落地路径.md) §2 的路线改造（首推二维功能区布局）。

## 5. 指标定义速查

| 指标 | 定义 |
|------|------|
| **重复搬运段数** | 按功能区分别统计：该功能区卸货序列（x 从尾门往里）的门店分段数 − 覆盖到的门店数。跨功能区卸货不计（品类隔离下本来就要分区取货）。理论下界 0。 |
| **空间分配降级车次** | `allocation_tier ≥ 2` 的车次数。等级 1 = 严格功能区；2 = 功能区仅作偏好（可越区）；3 = 降级为未做空间分配；**0 = 该方案本就不做空间分配（不适用）**。 |
| **越区箱垛数** | 落位超出所属功能区边界的箱垛数。等级 0 与等级 3 的车次不按越区计。 |
| 容积利用率 | 已装载货量体积 / 已用车辆车厢容积之和 |
| 未装载整箱垛 | 所有车次装不下的整箱垛数量；> 0 即方案不可行 |
| 可执行 | 全部线路同时满足时间窗达成、单车在线时长 ≤ 10h、累计等待 ≤ 150min |

## 6. 复现

```bash
# 30 门店算例（实测约 3 分钟）
python -m cityload.cli all --config configs/default.json --out reports

# 8 门店算例（约 2 秒）—— 空间分配生效的场景，3D 示意图由它生成
python -m cityload.cli all --config configs/test.json --out reports/compact
```

> 换随机种子重跑只需复制配置改 `seed` 字段。相对关系的稳健性：
> 在 8 门店规模上，空间分配生效与倒腾大幅下降是可重复的；
> 30 门店规模上的降级同样可重复。
