**设计原则**：业务规则（`categories.py`）与算法（`packing.py`）分离。
业务方改规则表即可调整装载策略，不需要读算法代码。

## 3. 关键设计决策

### 3.1 为什么用「整箱垛（Block）」而不是逐箱计算

同一门店同一 SKU 的整箱竖直码垛成一个 `Block`。好处：

- **规模**：2417 箱 → 约 700 个 Block，求解从分钟级降到百毫秒级；
- **符合实际**：仓库发货就是按箱码垛，现场也是整垛搬运；
- **语义清晰**：Block 自然携带「单柱可码几箱」这个 SKU 属性。

车厢变矮时，`normalize_blocks_for_height` 会把过高的柱按可用高度重新拆分。

### 3.2 为什么排线要用「折减后」的容积

排线与配载是两个阶段，最容易出的问题是**割裂**：
排线假设车厢能装 100%，排出一堆根本装不下的“大单”。

本方案的做法：排线阶段按**装载器实测可达效率**（`planning_volume_derate`，默认 0.55）
折减车厢容积，最终由 3D 配载器**回检**是否真的装得下，装不下就升级车型重装。
这个折减系数是两阶段之间的接口，必须实测标定，不能拍脑袋。

### 3.3 为什么车型指派要「先试装，再定车」

按体积估算选车，会选出「体积够但形状装不下」的车。本方案对每条路径
按单位成本从低到高**逐个车型真跑一遍配载器**，第一个装得下的就是结果。

副作用是好的：**装车装得紧，就能用更小更便宜的车**，
装载效率的收益会直接传导到成本指标上，而不是停在装载率里。

### 3.4 为什么发车时刻是决策变量

固定 06:00 发车会让服务下午时间窗的线路在现场干等数小时，
在线时长直接爆掉（实测出现 17.7 小时的线路），方案不可执行。

对固定访问顺序，令 `c_i` 为自中心仓出发到第 i 站的累计行驶+服务时间，
则发车时刻 `t` 需满足 `t + c_i ≥ tw_start_i`（否则等待）与
`t + c_i ≤ tw_end_i`（否则误时）。使等待最小的发车时刻有解析解：

```
t = max(仓开时间, max_i (tw_start_i − c_i))      可行上界 = min_i (tw_end_i − c_i)
```

### 3.5 为什么对照实验用 2×2 消融

「总成本降了」这种结论无法回答评委的追问：**降的是路径还是装载贡献的？**

A/B 共用同一组路径、C/D 共用同一组路径，装车器与排序规则完全一致，
唯一变量是「是否启用空间分配」。这样：

- A→C 单独反映**路径优化**的贡献；
- A→B 单独反映**空间分配**的贡献；
- D 是两者叠加。

## 4. 复杂度与性能

| 环节 | 复杂度 | 实测（30 门店 / 2417 箱） |
|------|--------|--------------------------|
| 节约算法 | O(n² log n)，n=门店数 | < 0.1 s |
| 2-opt | O(n²) × 轮数，逐路径 | < 0.1 s |
| 单次装车 | O(B × P × B_band)，B=箱垛数，P=候选点数 | 0.05–1.5 s |
| 车型试装 | 最坏 车型数 × 单次装车 | 每路径 1–3 次 |
| 路径批量搜索 | 候选批量数 × 指派 | 2–6 次指派 |
| 全流程 | — | **约 3 分钟**（实测 185 s，单线程 CPU，Windows） |

**性能优化点**（都直接影响结果质量，不是纯粹的提速）：

1. 候选落位点用 `bisect.insort` 有序维护，扫描可就地提前退出 → 候选集可以完整保留，
   不再因性能而被人为砍掉高层候选点；
2. `by_band` / `by_top` 两个空间索引把相交与支撑计算从 O(全部箱体) 降到 O(同高度带)；
3. 单柱高度限制在车厢可用高度 55%，使高度方向能形成两层，
   装载率显著提升的同时也降低了单次装车的搜索深度。

## 5. 可测试性

45 个单元测试（`python -m unittest discover -s tests -v`，实测 9.2 秒），覆盖：

- **领域层**：算例可复现、订单引用完整性、箱垛拆分与箱数守恒、几何相交判定；
- **空间分配层**：功能区覆盖整条车长且顺序正确、箱垛高度重整、越区检查；
- **配载层**：无几何违规、无货位重叠、箱数守恒、禁压规则、重货置底、
  支撑率、交付对齐确实降低重复搬运段数；
- **排线层**：全部门店被服务且仅一次、节约算法确实缩短里程、时间窗可行、
  2-opt 不劣化、容积越小路径越多；
- **端到端**：四方案齐全、无未装载、门店全覆盖、结果可复现、
  CSV 往返不丢需求、报告与 3D 产物齐全。
