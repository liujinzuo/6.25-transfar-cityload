# 03 · 空间分配与品类码放（核心设计）

本文档说明本方案的核心：**车厢空间怎么分、不同品类的货怎么摆**。

---

## 1. 为什么“分区”这件事很容易做错

直觉做法是把车厢沿车长按门店切成条，一家一条。实测这是错的，而且错得很难看。

在我们这套算例上（30 门店 / 2417 箱 / 45.5 m³，单车 6.8m 厢式）：

| 做法 | 容积利用率 | 未装载箱垛 |
|------|-----------|-----------|
| 不分区，全部货物全局按尺寸码放 | 27.8% | 0 |
| 按「门店 × 功能区」切成细条（细条宽 150–400mm） | 23.6% | **45** |
| 功能区内逐店顺序码放（本方案） | 26.4% | 18 |

原因很具体：细条宽度只有一两百毫米，一个门店在一个功能区里的货**只能叠成一根高塔**。
高塔很快顶到车厢天花板，而车厢其余部分还空着 —— 货物装不下，只能向全车逃逸，
功能区随之彻底失效（实测越区后各功能区的箱体散布在整条车长上）。

**结论：空间分配必须是“粗粒度硬隔离 + 粗粒度内的顺序码放”，而不是“细粒度切片”。**

## 2. 一级空间分配：品类功能区

### 2.1 排列规则

功能区沿车长的排列由 `categories.ZONE_ORDER_FROM_DOOR` 给出，**越靠前越靠近尾门**：

```
尾门 ← 冷链温控区 │ 日化隔离区 │ 常规药品区 │ 精密器械区 → 车头
        最先取用      独立成段      主力货量      稳固靠里
```

| 功能区 | 承接品类 | 放在这个位置的业务理由 |
|--------|----------|----------------------|
| `COLD` 冷链温控区 | 冷链药品 | 车辆到站后需**最快**转入冷链柜，贴尾门开门即取 |
| `ISOLATED` 日化隔离区 | 日化耗材 | 易泄漏、有气味，独立成段**避免与药品交叉污染** |
| `AMBIENT` 常规药品区 | 口服药品 / 外用药品 / 保健品 | 主力货量，居中便于分拣 |
| `PRECISE` 精密器械区 | 医疗器械 | 禁压、不怕位移但要稳固，放最里侧 |

配载器从**车头侧**（`zones_in_packing_order()` 的逆序）开始向尾门码放，
确保先装的靠里、后装的靠门。

### 2.2 长度分配：闭环回检，而不是一次性估算

长度分配分两阶段：

**初分配** —— 按功能区在本车次的**体积占比**分配，并以该功能区最大箱垛的
最小底面边长为**保底长度**（保证任何一个箱垛都放得进去）：

```
floor_total = Σ min_len(zone)
extra       = max(0, L − floor_total)
weight(zone) = min_len(zone) + extra × vol(zone) / Σ vol
zone_len(zone) = weight(zone) × L / Σ weight
```

**闭环回检** —— 按体积占比分配只是估算，实际能否装下取决于装载器。
所以分配结果要接受试装检验：

```python
zone_segs = allocate_space(...)                 # 初分配
for _ in range(zone_realloc_rounds):            # 默认 4 轮
    placed, left = _pack_store_major(...)       # 试装
    if not left:
        break                                   # 全装下了，分配有效
    need = 按功能区归集未装载货物的体积
    weights = {z: base_vol[z] + 2.0 * need[z]}  # 装不下的功能区加长
    zone_segs = _allocate(weights, mins, L)     # 其余相应缩短，重新试装
```

**空间分配本身是被求解出来的**，而不是拍脑袋的固定比例。

## 3. 二级分配：功能区内按交付顺序逆序逐店码放

功能区内**不再切细条**。码放顺序为：

```
for zone in 从车头到尾门的功能区顺序:
    for store in 交付顺序的逆序:          # 最后交付的先装 → 落在功能区里侧
        for block in 本店在该功能区的箱垛，按尺寸从大到小:
            落位
```

效果：**每个门店的货在每个功能区内自然聚成连续的一段**，
先装的（最后交付）在里侧，后装的（最先交付）在门口侧。
卸第 k 站时只需到各功能区取出属于该站的那一段，不必挪动别站货物。

这一点由指标直接验证：**重复搬运段数**（见 `docs/05-评测结果.md`）。

## 4. 品类码放规则

规则表：`cityload/categories.py`。

| 品类 | 功能区 | 单箱可承压 | 重货置底 | 优先卸货 | 不相容品类 |
|------|--------|-----------|---------|---------|-----------|
| 冷链药品 | COLD | **0 kg（禁压）** | — | ✔ | — |
| 医疗器械 | PRECISE | **0 kg（禁压）** | — | — | 日化耗材 |
| 口服药品 | AMBIENT | 45 kg | — | — | 日化耗材 |
| 外用药品 | AMBIENT | 30 kg | — | — | 日化耗材 |
| 保健品 | AMBIENT | 50 kg | — | — | 日化耗材 |
| 日化耗材 | ISOLATED | 60 kg | ✔ | — | 药品与器械全类 |

### 4.1 禁压上限（按重量，而不是按层数）

早期版本用“上方最多压几个箱垛”来建模，结果是：为了满足层数限制，
货物码到车厢高度的 45% 就压不上去了，装载率崩掉。
改用**重量分摊**后既符合物理，也放开了空间：

```
压载分摊：share = 候选位底面与支撑箱顶的重叠面积 / 候选位底面积
校验：    load_above[支撑箱] + 本箱重量 × share ≤ 支撑箱的 max_load_above_kg
```

冷链与精密器械的 `max_load_above_kg = 0`，意味着**它们上方永远不放任何货**。

### 4.2 品类不相容（防交叉污染）

`incompatible` 中列出的品类**不得直接上下相邻**。校验是双向的：

```python
if below.category in incompatible(cand.category): return False
if cand.category in incompatible(below.category): return False
```

日化耗材与全部药品/器械互斥，因此日化既不会压在药品上，药品也不会压在日化上。

### 4.3 重货置底

日化耗材标记 `heavy_bottom=True`，其**底面**离地高度必须 ≤ 500mm。
这里有个真实的坑：如果按**顶面**（`z1_mm`）判断，任何高度超过 500mm 的箱垛
即使放在地板上也会被判死，规则直接失效。必须用底面 `z_mm`。

### 4.4 易碎件置顶与底面支撑率

- 易碎件上方不得再压任何货；
- 每个候选位底面至少 75% 被下方箱顶或车厢地板支撑（防止“悬空搭桥”）。

### 4.5 单柱高度上限（间接但影响最大的一条）

一个箱垛如果直接码到接近车厢顶，上方就再也叠不了东西，**车厢上部整片浪费**。
因此单柱高度被限制在车厢可用高度的 **55%** 左右，使两柱可以叠起来。

这条规则不写在流程图上，但对装载率的影响比前面几条加起来还大，
属于「看起来是参数、实际上是设计」的那一类。

## 5. 三级降级：可行性优先，但降级必须可见

品类隔离是合规要求，但「装不下」同样是不可交付的。因此 `pack_route` 按三级降级，
并记录最终生效的等级到 `VehicleLoad.allocation_tier`：

| 等级 | 策略 | 合规性 | 可行性 |
|------|------|--------|--------|
| 1 | 严格功能区 + 分配闭环回检 | 完全隔离 | 取决于装载器 |
| 2 | 功能区仅作落位偏好（可越区） | 部分越区 | 较好 |
| 3 | 不做空间分配，全区集中码放 | 无隔离 | 保证装下 |

降级**不被隐藏**，而是作为指标暴露：
`relaxed_loads`（等级 ≥ 2 的车次）、`unallocated_loads`（等级 3 的车次）、
`zone_violations`（越出功能区边界的箱垛数）。
评审或业务方可以直接看到「为了装下，牺牲了多少合规性」。

## 6. 落位算法：带空间索引的极值点启发式

每个箱垛的落位从**候选点集合**中选取。候选点来自已放置箱体的角点（极值点）：

```
候选点 = { (z, x, y) }  ←  每放一个箱垛，追加 6 个角点
```

对每个候选点尝试两种水平朝向，逐条校验上文的全部规则，取
**（越区惩罚, z, x, y, −长边）最小**的可行解。

工程上有两个必须做对的地方，否则算法会因为性能而被人为削弱：

1. **候选点不能砍**。早期版本为防止候选集膨胀，超出上限就按 z 排序丢尾部，
   结果把高层候选点全丢了 —— 码放永远上不去，装载率被自己锁死。
   现在改为**空间索引 + 提前退出**：候选点按 (z,x,y) 有序维护（`bisect.insort`），
   扫描到 z 超过已知最优解 + 松弛量立即退出，因此候选集可以完整保留。
2. **相交判断要按高度带索引**。`by_band` / `by_top` 两个字典把相交与支撑计算
   从 O(全部箱体) 降到 O(同高度带的箱体)，单次装车从秒级降到百毫秒级。

## 7. 关键参数与取值理由

| 参数 | 取值 | 理由 |
|------|------|------|
| `min_support_ratio` | 0.75 | 底面 3/4 被支撑即可，兼顾稳定性与空间利用 |
| `max_height_ratio` | 0.95 | 留 5% 顶部装卸间隙 |
| `max_block_height_ratio` | 0.55 | 让两柱能叠起来（见 4.5） |
| `heavy_bottom_max_z_mm` | 500 | 重货底面必须落在车厢下层 |
| `zone_height_slack_mm` | 400 | 为留在本区最多多付 400mm 高度代价 |
| `zone_realloc_rounds` | 4 | 分配回检轮数，超过后收益递减 |
| `planning_volume_derate` | 0.55 | 排线时按装载器**实测可达效率**折减车厢容积，避免排出装不下的“大单” |

`planning_volume_derate` 是排线与配载之间的**接口标定值**，
它把「装载器实际能装多满」这个事实反馈给排线阶段。
标定错了就会出现「路线排得很漂亮，但一车货根本装不下」这种典型割裂问题。
